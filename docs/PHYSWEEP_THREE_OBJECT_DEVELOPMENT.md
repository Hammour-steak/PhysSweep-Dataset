# PhysSweep 3obj 开发设计文档

日期：2026-09-07

版本：设计草案 v5（补组内执行一致性与接触统计契约，限定修复范围）

状态：待实现与试产验证；本文不代表 3obj 生成链路已经可用，也不启动采样或渲染。

## 1. 目标与开发边界

建立与现有 1obj、2obj 一致的三动态物体数据生成链路：可复现采样 base metadata、执行物理准入、派生单物体单参数 sweep、固定组内镜头、渲染、发布并完成验收。

3obj 的主要新增内容是三物体的初始运动、交互关系和验收规则。对象身份、物理执行、轨迹格式、渲染、发布尽量复用现有实现。不能将 2obj 工程整套复制后仅修改数量，也不提前建设任意 N 物体框架。

首轮范围：generic、球体、平面支撑、接触事件有明确先后的交互，以及两物体交互加无直接接触物体的对照。随后按验收结果引入混合形状、斜面和台球；被动弹珠台、轨道弹珠、空中交互及接近同时碰撞后续接入。专用 asset 分支不因增加对象数量自动纳入范围。

首轮限制是开发顺序，不是正式数据只能包含三球和平面。正式支持范围要同时声明对象类型、运动、物理场景、视觉环境、纹理/材质、光照和相机的覆盖，见第 3、8、14 节。

三个动态物体指三个参与刚体动力学仿真的对象，不包括静态支撑、轨道、桌边和装饰物。动态物体允许初始静止，不能用“初始速度非零”判断其是否属于动态对象。

## 2. 设计约定与待验证事项

### 2.1 本版采用的设计约定

- 对象身份固定为 `object_a`、`object_b`、`object_c`，对象索引分别为 0、1、2。
- 每个 base 只对 `object_a` 做 sweep，目标索引显式配置为 `[0]`。
- 每组包含 1 条 base、12 条派生 sweep，共 13 条样本。
- base 满足所声明的运动和镜头规则；sweep 不因运动结果变化而被重新筛选。
- 一个 sweep 只改变一个目标物体的一个规定材料参数；非目标物体的输入参数、全部初始状态、几何、环境及视觉输入保持不变。非目标物体的后续轨迹可以因交互而改变。
- 正式样本沿用共同 metadata、trajectory、group manifest 格式，不输出逐帧 PNG mask。
- 正式文本沿用 `text.caption`、`text.object_mentions`，覆盖三个对象，仅描述确定的初态与环境事实，同组 base/sweep 的文本一致。
- 用独立 work ID 和源码版本开发，不修改现有正式 1obj/2obj 数据及冻结的生产输入。

这些是本文的实施基线。正式配额、数值阈值及新增运动覆盖在试产后冻结，不把讨论中的建议误写为已经通过验证的事实。

### 2.2 需要通过试产确定

| 项目 | 当前处理方式 |
|---|---|
| 总条数、各 family 配额 | 未确定，不直接沿用 2obj 的生产比例 |
| 各运动模板及干预角色占比 | 先统计有效覆盖与通过率，再确定 |
| 物体类型、场景、纹理和相机覆盖 | 在合法来源与兼容条件内分配；不能只用运动通过率决定 |
| 三者独立对照是否进入正式集 | 作为候选对照；首轮不要求大量覆盖 |
| 接触事件阈值、时间容差、可见性阈值 | 在规则配置中显式给出，通过试产校准 |
| 混合形状、复杂支撑和专用分支 | 分批接入，每批独立验收 |
| 接近同时碰撞 | 先验证求解稳定性，暂不作为首轮必选模板 |
| 渲染时间与资源需求 | 用正式分辨率实测，不按 2obj 简单乘系数 |

## 3. 运动分类：交互关系、运动模板与参数变化

之前讨论的“连锁碰撞、连续碰撞、双向汇入、独立对照”保留为起步模板。它们不是互不重叠的接触图分类，需要分层表达。

术语分开使用：`family` 指 generic、billiards 等生成分支；交互关系指动态对象接触结构；运动模板指初态与事件模式；对象类型指几何/资产语义；场景类型指物理支撑与环境。不能把“三球”“连锁碰撞”“实验室背景”混成同一分类轴。

### 3.1 第一层：交互关系

以三个动态物体为节点，以观测区间内实际的动态物体间接触为边，接触距离容差按规则冻结，不能因为某次碰撞造成的位移小就删掉这条边。AB 与 BA 是同一无向物理接触对；有序事件和语义角色另行记录。

| 建议标识 | 定义 | 验收含义 |
|---|---|---|
| `connected_three` | 三个节点属于同一接触连通分量 | 三者都参与同一交互过程；AB、BC 两条边即可，不要求三对都接触 |
| `pair_plus_independent` | 恰有一对接触，第三个物体与这两者没有直接接触 | 两物体交互加无直接接触物体的对照 |
| `independent_three` | 三对之间均无直接接触 | 三者无直接接触的候选对照 |

静态桌面、轨道等共同接触不能算动态物体之间的边，否则所有物体放在同一桌面就会被误判为三者交互。

图只表达直接接触关系，不等价于因果图。这里“独立”是“无动态物体间直接接触”的简称，不表示统计独立；共享重力、初态构造、场景和采样先验仍可能形成相关性。共同静态 fixture 记录在场景中，不伪造物体间接触边。判断限定在整个 4 秒记录区间内，不宣称区间之外永远不会碰撞。可运动的共享平台或其他额外动态机构会改变对象数量与耦合范围，不属于本版三动态对象模型。

### 3.2 第二层：运动模板

以下 P、Q、R 表示运动角色，避免与固定对象 ID A、B、C 混淆。

| 模板 | 起步初始状态 | Base 必须成立的事件 | 初版限制 |
|---|---|---|---|
| 连锁传递 | P 运动，Q/R 静止，物体初始分离 | P–Q 接触在前，Q–R 接触在后，且运动变化支持传递解释 | 先用球体、平面、明确事件间隔 |
| 同一物体连续碰撞 | P 运动，Q/R 初始静止 | P–Q 接触后，P–R 接触 | 通过布局和偏心量产生后续运动，不施加中途控制 |
| 双向汇入 | P/R 运动，Q 初始静止 | P–Q 和 R–Q 均发生 | 首轮要求可区分的先后顺序；接近同时单独建模板 |
| 两物体交互加独立对照 | P/Q 按指定双物体模板运动，R 独立运动 | P–Q 成立，P–R/Q–R 均不发生 | R 必须可见，且运动身份明确 |
| 三者独立对照（候选） | 三者按各自声明运动 | 无动态物体间直接接触 | 后续决定覆盖规模 |

连锁传递与双向汇入可以具有同一个无向接触图，依靠初始运动和事件关系区分。对于初始就在运动的 Q，不能仅凭 P–Q、Q–R 的时间顺序命名为“因果传递”；可使用“有序多次碰撞”等较弱的描述。

每个模板还应声明允许的额外接触。例如后续出现 P–R 接触，是否仍符合当前模板，必须由规则决定。不能只检查必需事件、忽略会改变类别含义的额外接触，也不默认禁止所有后续再接触。

**模板统计采用唯一主模板。** 主模板在采样前确定，base 只按该模板的冻结规则准入；实际轨迹若还满足其他模板，可在内部审计中记录附加事件标签，不重复占据多个模板的配额。不能在原模板失败后把样本改归到更容易通过的模板以补数。完整轨迹的接触图、设计主模板和附加事件是三个不同字段含义；sweep 的观测标签可以变化，不据此改写组的 base 主模板。

连续碰撞不能默认采用同质量三球共线正碰布局：第一次碰撞后 P 可能不再有足够运动完成第二次碰撞。应先验证偏心量、质量比和第二个物体位置的可行域，禁止通过碰撞后重置速度或临时施力补足动作。斜面上“初始静止”也不保证接触前一直静止；新增斜面模板需检查接触前运动，不能直接继承平面的传递解释。

### 3.3 第三层：允许的运动变化

| 维度 | 可选变化 |
|---|---|
| 初始运动 | 一动两静、两动一静、三者运动 |
| 运动方式 | 滚动、滑动及允许的转换；转动初态与支撑关系显式声明 |
| 相对方向 | 同向追赶、相向、交叉 |
| 接触几何 | 正碰、不同偏心量的碰撞 |
| 事件时间 | 明确顺序、不同事件间隔、后续接近同时 |
| 初始姿态与物性 | 稳定姿态、角速度、角色质量比、摩擦与恢复系数 |

各维度不能直接做无约束笛卡尔积。模板先声明兼容集合，再在集合中采样。例如可连续传递的球体组合，不代表任意方块姿态、偏心量和速度都能复用。

初版规则表至少包含：模板 ID、交互关系、角色定义、允许形状、初始状态构造、参数范围、必需接触、禁止/允许额外接触、事件顺序、运动证据、镜头检查时刻和适用干预角色。

速度、间距、偏心量和事件时间应联合构造，不能独立抽样后指望都能在 4 秒内完成。按对象尺度定义相对间距、偏移和速度范围，同时保存实际 SI 单位值。关键事件应留有可观察的前后时段；初始角速度和姿态在组内冻结。“滚动”需要验证转动与平移关系，不把所有移动的球都标为纯滚动。

对象形状与尺度另见第 3.4 节，场景、纹理、相机另见第 8 节，避免在运动表中重复定义同一维度。第一轮按支撑场景中的初始速度构造运动；后续自由滑行、转动变化和碰撞均交由物理引擎演化。接触、静止和滚动阈值按作用分别命名，静止判定包括所需的线速度与角速度条件。

### 3.4 对象类型与形状组合

- 几何覆盖至少区分球、方块、圆柱；同类三对象、两同一异、三种混合是候选组合层次，不要求每种都能用于全部模板。
- 组合按运动角色有序描述，例如“发起球—中间方块—末端球”与“发起方块—中间球—末端球”具有不同兼容性，不能只用无序形状集合做覆盖统计。
- 几何类型、可视资产语义、碰撞代理分开记录。看起来是某种日常物体不意味着它能用球体碰撞代理；不能为了扩大语义类别而替换真实代理。
- 初版用基本几何验证；后续可复用已有合格资产来源，但需检查其碰撞代理、支撑姿态、重心/惯量约定、尺度与视觉包络。独立 asset 生成分支与“generic 使用合格资产来源”不是同一事项。
- 质量比和尺寸比按角色组合统计；相同外形可有不同质量，但应处于声明的 base 先验中。Sweep 的相对质量干预不再被 base 的采样先验裁剪。

## 4. 对象身份、角色、来源与去重

### 4.1 身份与角色分离

`object_a` 是固定 sweep 目标，不固定为最先运动的物体。采样前确定目标在当前模板中的角色，可覆盖发起者、中间传递者、共同受撞者、最终接受者，以及对照组中的独立物体。

同一组中 role→object ID、object ID→index、几何绑定、材料绑定和来源绑定均不可变。Sweep 改变运动结果后，原角色描述代表 base 的设计身份，不重新根据结果给对象改名。

两物体交互加独立对照至少区分两类目标：干预交互参与者、干预独立物体。二者分开统计，比例在试产后确定。

### 4.2 复用来源，不继承旧验收结论

复用现有对象与支撑资产、材料先验和 source binding。generic 继续从适合对象集合编译器的单物体来源构建三物体场景，不直接给某条已验收 2obj metadata 随意追加 C。

新对象组合、初始布局、镜头请求均重新验证。旧来源中的 admission、双物体语义、相机结论不能作为新场景已通过的证据。

来源必须经过“正式 base 清单 → 样本 provenance/lineage → 原始 generation metadata → 对象/host 候选”的已验证绑定。`object_collection.py` 实际消费的是内部 rigid metadata v1，不能将正式 base sample v12 直接当作它的输入，也不能仅修改 schema 名称伪造转换。

已确认来源入口存在前置缺口：`two_object_sources.py` 仍限定 base sample v11、base pipeline v12，而当前 maskless 正式 1obj 使用 sample v12、pipeline v13。需要补当前版本的严格读取与哈希链验证，再提取可共享的来源解析；旧冻结版本按其原有契约恢复，不一概放宽为“任意版本都可读”。这是新采样入口的兼容问题，不意味着已发布的数据内容失效。

### 4.3 去重口径

- 物理唯一性与外观变化分别统计；同一物理场景换背景不能增加物理覆盖计数。
- 同一场景仅交换 A/B/C 名称或对象数组顺序，不算新物理场景。
- 为三对象构造忽略标签排列的物理签名，同时保留实际对象 ID 绑定用于复现与 sweep。
- 相同物理场景若未来需要增加另一个干预目标，应表达为同一 base 的额外 target，而不是伪造新的 base；这不属于本版单目标生产方案。
- 镜像、整体旋转、相似参数变化是否独立计数应有明确政策，并报告近似重复情况。
- 对象来源、支撑来源的复用上限在试产后配置；不机械沿用 2obj 的上限与配额。

去重与复现采用不同口径：**物理场景签名**包含碰撞几何、初态、材料、重力及支撑/环境等物理定义，排除仅用于命名的 ID、主模板标签、文字和外观。**执行绑定**另记录时间采样、仿真频率、solver、引擎和代码版本，复用现有计划/记录哈希。只改执行设置不能增加唯一物理场景数，也不能让同一场景跨训练/验证集合；其数值结果仍分别留证，不能混为一次执行。

物理签名的单位、数值序列化和对象排列归一化规则应明确，不能只比较三对象位置或仅对文件做哈希。去重不自动忽略世界旋转或镜像，因为重力、边界和环境可能破坏这种等价性；近似重复另行报告，不用任意舍入掩盖实际物理变化。视觉签名绑定外观、纹理、背景、光照和最终相机。这些是内部统计与引用口径，不要求为正式 metadata 新增一组顶层字段。

从采样阶段保留 base group、物理签名及 1obj 来源 lineage，方便下游按完整组划分数据集；同组和重复物理场景不能跨训练/验证集合。若以后评估资产或场景泛化，再制定对应来源留出策略，不在本次开发中擅自切分数据，也不将所有共享任意资产的样本强制并成一个巨大分组。

## 5. Metadata 与内部证据

### 5.1 内部候选 metadata

候选 metadata 应表达三个对象的完整初始物理状态、来源、支撑与碰撞环境、交互设计、相机请求和随机种子。候选文件是待仿真的输入，不伪装成已有 video/trajectory 的正式样本。

建议在内部交互契约中统一承载下列信息，具体字段结构在实现首阶段冻结：

| 信息 | 内容 |
|---|---|
| 设计身份 | 交互关系、运动模板、角色到对象 ID 的映射 |
| 事件要求 | 必需接触对、禁止接触对、允许额外接触策略、先后关系和时间容差 |
| 运动要求 | 按角色定义的静止/运动初态，以及接触前后运动证据要求 |
| 采样记录 | 物理 coverage cell、视觉分配、种子、尝试编号、物理/视觉签名、来源绑定 |
| 观察要求 | 初始帧、各关键事件前后、后段运动的检查策略；相机族、纹理/光照请求及最终冻结结果 |

上述为新内部契约的设计要求，不表示现有 2obj 字段已经接受这些键。公共函数应接收明确的对象列表、目标列表和规则对象，不靠场景 ID 字符串猜测对象数量或运动类型。

### 5.2 观测证据与采样意图分开

物理审计记录实际接触事件、轨迹指标、失败原因、适用规则版本和执行环境。意图声明不能直接充当观测结论。

事件记录建议包含：两个稳定对象 ID、接触开始/结束子步、接触时间、最小接触距离、接触前后速度等实际可获得的信息。若后端提供的是接触力，不直接命名为冲量；需要冲量时按明确方法积分，并记录方法。

额外的交互事件和覆盖统计保留在内部审计中。正式 `trajectory.npz` 不为本次开发随意增加必需字段，正式 metadata 也不新增一批重复的 3obj 顶层描述。

### 5.3 Caption 与训练 prompt 的边界

**正式 caption 是生成链路必需内容。** 复用 2obj 的初始事件描述原则，不能将“连锁传递”等 base 的准入标签原样变成对所有 sweep 的结果承诺，也不照搬旧 1obj 中“必定反弹/返回/进入终点”的结果句。

- `text.caption` 使用英文，包含三个对象以及支持该场景理解的初态、相对方向和真实支撑/环境；不要求机械列出全部纹理或渲染参数。
- 可以写“一个球朝另外两个初始静止的球所在方向运动”，不能写“它将依次撞上两球、最终把第三球撞出桌面”。对照也描述不同初始路径，不承诺任何干预下永不相撞。
- 同组最终 caption 和 mention 绑定保持一致；不读取 sweep 轨迹生成动作文本，不添加质量档位、结果标签或内部场景 ID。确需数值物理条件时由下游结构化条件承载，不混入这段共同 caption。
- `text.object_mentions` 覆盖三个 ID，字符区间与最终句子对应。重复出现 `the ball` 不得被字符串替换误绑到另一个物体；对象数组索引、运动角色、提及顺序分别验证。
- 同形物体优先用已绑定且可核实的外观/初态关系区分。描述颜色必须来自实际来源，描述屏幕左右必须与最终相机投影一致；首版优先使用不依赖视角的真实描述，避免为了文本引入额外相机后改写流程。A/B/C 的内部 ID 不能替代人可理解的指称，也不要求三个物体使用永久固定的颜色编码。

当前实现有明确缺口：`build_object_identity` 完整分派只覆盖 1obj/2obj；三物体仅有 `three_ball_collision` 的旧台球兜底，描述为三个物体相互碰撞。新的 generic 三物体模板将被拒绝，旧兜底也不满足本版反事实文本原则。D1 前必须新增明确的三物体初始事件模板和模板版本分派，未知模板失败，不降级成笼统的“物体相撞”。

当前共同 `_clean_text` 按原始 mention 顺序查找并规范化标签。首版新模板应让三个对象的首个绑定提及按固定对象顺序出现，以复用此契约；后续若允许任意语序，应先实现并验证显式 span 绑定，不能同时假定任意角色顺序和现有字符串查找天然兼容。角色可以轮换，不需要靠改变首个提及顺序来表达。

**完整训练 prompt 的封装是后续接口。** 当前 `tools/training_export/one_object_prompt_contract.py` 检查恰好一个动态对象，并写入 `Exactly one dynamic object`，不能直接用于 2obj/3obj。届时应围绕共同 caption 增加按对象数量校验的薄封装，明确固定相机及对象身份/外观/背景保持，不得把“对象保持一致”写成“位置始终固定”。本次开发必须交付合格的三物体 caption，但不因此扩展为实施整套训练导出。

### 5.4 冻结发生在各自阶段

| 阶段 | 冻结内容 | 后续允许产生的派生记录 |
|---|---|---|
| 候选 metadata | 来源、物理初态、主模板、seed、视觉/相机请求、有效的初始事件文本与身份 | 审计、相机候选及解析结果；不回写改变原候选 |
| 物理准入 | 输入绑定、运行配置、原始轨迹、事件与决定 | 引用这些证据的 base 相机确认与 sweep 记录 |
| 视觉/渲染准备 | base 确认的相机、解析材质与曝光、最终文本、渲染请求 | 按同一冻结视觉/文本生成整组渲染输入 |
| 正式发布 | 实际媒体、轨迹、正式 metadata 和全部哈希引用 | 校验报告；内容修正采用新版本，按依赖范围重建并整组验收 |

候选字段与后续解析字段用新记录和哈希关联，不能为了补相机或 caption 覆盖 metadata-only 的输入。若视觉选择改变几何、物性或初态，则回到新候选；若仅采用预先允许的相机/曝光选择，则属于正常的视觉绑定阶段。同组冻结的是实际解析后的值，不只是同一份随机配置名称。

修复按依赖范围处理：物理输入或执行配置改变，重跑受影响组的物理及下游产物；仅相机、曝光或文本修正，重建相应的整组下游产物并更新绑定，无需重跑未受影响的物理。缺失或损坏文件若能按冻结记录恢复为原哈希，可补回并重新校验；无法恢复为原内容时按新版本处理。整组验收不等于每次从零重算，已发布的内容版本不得被不同内容静默覆盖。

## 6. Base 物理准入

### 6.1 通用执行与完整性检查

- 确认恰有三个不同的动态对象，ID、index、运行时 body 与轨迹数组一一对应。
- 检查 AB、AC、BC 全部物体对的初始分离/穿透，以及每个物体对支撑、环境的初始穿透。
- 检查质量、尺寸、惯量、材料值、姿态和时间设置合法，运行时设置与 metadata 一致。
- 所有轨迹数值有限，时间轴正确，求解器与接触配置有执行证据。
- 检查异常深穿透、非物理数值爆炸等问题；角色或运动相关阈值与通用数值失败分开。
- 在需要时使用更高积分精度进行稳定性检查，但不默认对全部场景盲目提高仿真频率。

### 6.2 接触和事件时间

必须采集三对动态接触，不能复用“只看 bodies[0] 与 bodies[1]”的假设。

关键事件采用仿真子步时间。24fps 的输出轨迹可能把先后两次碰撞放进同一输出帧，因此不能仅凭输出帧索引判断先后。

规则区分几何接触记录与模板所需的有效碰撞事件。持续接触要合并为事件区间，并为短暂断开/重新接触规定处理方式，避免把持续挤压误记成多次新碰撞。阈值、时间分辨率及容差均记录在配置中。

接近同时采用相对于实际子步分辨率的明确容差。若同一子步内无法分辨先后，记录为时间分辨率内未区分，不编造顺序。

事件采集优先复用每子步已有接触记录：统一无向 pair key，去除从两个 body 视角收集到的重复记录，再派生各物体指标。不能把 AB 和 BA 当成两次碰撞，也不要为图、计数和时间各执行一套重复的全量查询。保留能够支持验收的紧凑事件区间及必要统计；默认不存全程每子步的所有接触点转储。

**事件去重不改变正式轨迹字段。** 现有 `contact_count` 表示适配器规范化后的、涉及该物体的接触点数量，包含适用的物体/环境接触；它不是接触对象数、接触图边数或累计碰撞次数。AB 对事件只记一次，但 A 与 B 各自的接触点统计都应包含这次接触，不能在一个对象上消掉。事件图与发生次数使用内部审计记录，共同发布字段的名称、单位、数组形状与统计含义继续保持一致。

### 6.3 按模板检查运动语义

- 连通交互组检查实际接触图连通性，不能让完全无关的 C 通过。
- 对照组检查指定的禁止接触在完整记录区间内未出现。
- 按模板检查必需事件、事件顺序和额外接触政策。
- 按角色检查运动，不使用全体相同的最小位移阈值；较重的接受者可能只产生小位移。
- “连锁传递”先采用 P 运动、Q/R 静止且初始分离的明确设计，结合接触前后运动变化支持解释。接触顺序本身不是一般性的因果证明。

失败要区分：候选输入非法、物理执行失败、数值完整性失败、base 运动语义不成立、base 镜头不合格。保留每类计数与原始候选记录，不能把所有失败都记成“采样失败”。

## 7. Sweep 设计与准入边界

### 7.1 组结构与参数

沿用单因素干预：质量、接触摩擦、接触恢复系数各 5 个水平，base 位于中间水平，另外 4 个水平形成派生样本。

每目标派生数量：`3 × (5 − 1) = 12`。

本版每组数量：`1 + 12 = 13`。

若以后干预全部三个对象，每组将是 `1 + 3 × 12 = 37`，需要重新规划；本版不采用。

目标列表在采样计划、派生、物理记录、渲染准备、source release、group manifest 和验收中全部显式传递 `[0]`。现有 `sweep_target_indices` 在省略列表时选择所有对象，因此任何阶段都不能依赖省略值。

质量干预沿用 2obj 的相对倍数 `[0.25, 0.5, 1.0, 2.0, 4.0]`。摩擦和恢复系数复用共同配置及对应 family 的合法范围。值需有限、合法、严格递增且可区分，base 精确保留为中间值。

物体材料参数不等同于物体对的实际等效接触系数。继续使用已验证的后端材料设置方式，记录对象参数和执行证据，不额外引入一个独立的“AB 摩擦”干预轴。

### 7.2 不变量

每条派生记录恰好改变 A 的一个规定材料字段。B/C 的运行时材料不变；所有对象初始状态、几何、对象顺序、fixture、环境、视觉随机种子、相机和渲染请求保持一致。

B/C 的位置、速度、转动和接触结果不属于这一不变量；要求它们在整段轨迹上与 base 相同，会错误地禁止三物体相互影响。

由质量变化必然带来的惯量等派生运行时变化应由既定物理规则计算并验证，不能把“单参数干预”错误理解为禁止其物理派生量变化。

同组 13 条必须使用一致的记录时长、输出时间轴、有效积分频率、求解器配置、非干预接触设置和执行代码版本；不能看到某个 sweep 的结果后单独提高其积分精度或修改稳定化参数。实际仿真频率以解析后的值为准，不能只比较名义配置；已有 `generic_integration_configuration` 会根据场景输入计算有效频率，应在组验证中比较其完整结果。跨组可以按冻结的场景规则采用不同设置，但必须各自留证，且不计为新的物理场景多样性。

base 在组中只存一次。正式 base 无 `sweep` 字段；派生记录明确目标 ID、index、轴、水平和 parent base 绑定。

### 7.3 Sweep 不按运动结果筛选

允许碰撞消失、增加、顺序变化、传递中断、某个物体静止或运动明显变化。这些是干预结果，不作为重新采样、逐条调整初速度或改变镜头的理由。

同样允许正确干预后运动近似不变，不能要求每条样本、每个参数轴或每个模板都有明显响应。应核对声明的参数确已传给引擎，并报告效果分布；不以速度差、位移差或视频差异达到某个下限作为正式采样准入条件。

仍需执行参数绑定、对象身份、数值有限性、时间轴、仿真完成、文件与哈希完整性检查。真正的数值/工程问题应调查并修复，不能为了凑配额换掉产生不同结果的样本。

如果某个极端干预暴露稳定性缺陷，暂停受影响组并记录；诊断可使用不同精度的独立执行。如果修复改变物理设置或冻结规则，建立新版本并完整重跑受影响组，不能将诊断结果只替换进其中一条。

检查项必须有显式类别、适用阶段和完整的预期清单：输入/身份/数值/文件检查属于硬要求；运动模板结果属于 base 质量要求，在 sweep 中为诊断。零次接触且记录完整可以是合法 sweep；事件证据缺失、检查项缺失或无法判定不能被当作“没有碰撞”而放行。不要通过失败名称的字符串前缀或“所有未知失败都 advisory”实现这一边界。

## 8. 场景、纹理、光照、相机与视频

### 8.1 物理场景与视觉环境分开覆盖

| 层次 | 候选内容 | 兼容与验收要求 |
|---|---|---|
| 物理支撑 | 地面平面、高架桌面、长/宽支撑；后续斜面 | 承载三物体初态和声明运动，按真实尺寸、边界与姿态检查 |
| 支撑与边界结构 | 桌腿、边缘、地板；专用桌边、柱钉和轨道 | 凡会产生碰撞者必须进入物理环境及 fixture 绑定 |
| 背景环境 | 简洁、家居办公、实验室、车库工坊、庭院等已有类别 | 根据现有来源可用性和场景兼容选择，不保证各类等量 |
| 视觉复杂度 | 简洁与适度布景、不同背景深度和色调 | 不让装饰持续遮挡动作区域，区分物理与纯视觉对象 |
| 专用 family | 台球、被动弹珠台、轨道弹珠 | 复用场景资产，重新设计三物体运动与关键事件，不强套 generic 规则 |

列出的背景类别来自现有 2obj 场景规则，可作为来源池；其材质/贴图/HDRI 是否实际可用仍需资源清单验证。相同平面换五种背景只增加视觉覆盖，不算五种物理支撑。

先做三物体布局的廉价几何检查：真实碰撞尺寸、对象与支撑尺度比、初始净空、支撑边界和环境障碍。再以仿真检查实际路径和事件。不能为了让三物体塞进画面而任意缩小物体或放大支撑，任何尺度变化都须进入新 base 物理输入并重新验证。

纯视觉背景不得在动作区域呈现会被物体明显穿过的实体障碍；有交互意义的墙、栏杆、桌沿必须有匹配碰撞几何。静态 fixture 的外观变化也不能暗中改变碰撞形状。源场景若本身缺少可验证的物理/视觉一致性，应拒绝该组合并记录原因。

### 8.2 纹理与视觉材质

纹理是独立设计维度，不能只用“外观随机”概括，也不能只换 RGB 颜色。

| 对象 | 覆盖项 | 约束 |
|---|---|---|
| 动态对象 | 源材质/贴图类别、颜色明度、图案尺度、纹理方向、允许的粗糙度与反射差异 | 优先复用已绑定外观；新参数变化仅对明确可参数化的材质开放 |
| 支撑表面 | 已有木质、涂层、石材、地面等实际可用表面族及其纹理尺度 | 表面外观与真实物理参数分别记录，不捏造不存在的资产 |
| 背景 | 环境材质、颜色、细节密度 | 与物体轮廓可区分，不过度吸引注意或形成遮挡 |
| 三物体组合 | 相同/不同外观族、适度对比、相近颜色但仍可区分的组合 | 以实例可辨认性验收，不要求固定三种强对比色 |

`object_collection.py` 会保留来源物体的 visual profile 和材料绑定。首轮通过选取不同合格来源实现外观覆盖；若后续需要新的程序化纹理或材质参数变体，必须在 base 采样阶段显式构造、记录生成配方/种子与来源，并通过既有视觉验证，不能在渲染时临时重涂。

视觉 roughness、metallic、base color、normal map 等不是物理摩擦/恢复系数。遵循来源的合理材料先验，同时在可行范围内交叉覆盖，避免“某颜色/纹理必然对应某质量或运动”。Sweep 无论改质量、摩擦还是恢复系数，都保持外观不变。

会改变轮廓或接触表面的几何 displacement 不归入纯纹理随机化；若启用，必须重新检查碰撞/视觉一致性并作为新 base 的几何变化记录。

三物体的颜色、纹理和图案不能固定对应 A/B/C 或发起/接受角色；在满足可辨认性的组合中按预声明种子分配并统计偏置。同形同色对象可能难以从首帧识别具体目标，base 观察策略必须考虑实例区分；不能仅凭内部 ID 存在就声称视频中身份可读。

若任务需要看出自转，适度非均匀纹理是可选观察手段；均匀球体不能只靠视频验证旋转方向，物理转动检查仍以轨迹为准。禁止用每个角色专属标记编码答案。

纹理实际加载、UV/程序化坐标、尺度、方向、哈希及许可归属应可追溯。缺图、拉伸、明显接缝、错误法线或过强高光等问题进入试产视觉检查。缺失贴图不得静默退成默认灰材质并声称完成纹理覆盖。

表面图案应随物体平移和转动保持绑定；记录实际使用的 UV/局部坐标方式，不能仅因纹理文件与 seed 相同，就忽略世界坐标投射造成的图案在物体上滑动。纹理局部坐标、几何局部坐标与轨迹姿态的对应关系随三物体回放一起验证。

### 8.3 光照与组内视觉冻结

在来源支持范围内覆盖 HDRI/环境光、主光方向与软硬程度、曝光及色彩配置。HDRI 既可能影响光照也可能出现在背景中，需要记录其真实用途；没有 HDRI 的场景不补造字段。

避免目标对象持续过暗、过曝、反光淹没纹理或阴影掩盖接触。光照覆盖也需要在运动和角色条件下检查，不能某类动作总是更亮。

所有解析后的 shader 参数、纹理坐标/随机种子、背景布置、灯光、HDRI 旋转、曝光、色彩管理和相机在 base 审核后冻结。复用外观适配/曝光修正时，应保存 base 最终结果并供 sweep 直接使用；不能每条 sweep 按它自己的画面重新自适应，否则引入额外视觉变化。

渲染请求与随机种子在组内一致，并保留渲染器版本和执行设置。固定输入不等于承诺不同硬件/执行环境逐像素一致，验收应区分参数不变量与渲染数值噪声。

首版沿用共同渲染预设，不为扩大覆盖另加景深、运动模糊、动态灯光、闪烁、运动背景等维度；已有预设中的相关参数显式继承并冻结，是否启用不能隐含变化。若预设妨碍高速事件可读性，应作为统一试产配置问题处理。

**组内 t=0 检查同时覆盖物理与画面。** 三物体的初始位置、姿态、线/角速度及视觉输入应一致；首帧须对应同一 t=0，不得先推进一步物理再输出。若模糊或其他时间采样会读取之后的运动状态，应在统一配置中避免首帧受到未来轨迹影响。试产比较整组解码首帧的构图、对象状态和外观差异，区分实际不一致与渲染噪声、视频编码误差，不要求 MP4 字节或解码像素绝对相同，也不新增正式首帧文件。

### 8.4 相机覆盖与确定方式

首版采用整个视频内固定的透视相机。后续如果加入移动相机，应单独设计固定的组内相机轨迹与审计，本版不默认加入跟随、自动变焦或镜头切换。

| 维度 | 覆盖与构造方式 |
|---|---|
| 相对方位 | 侧向、前斜向、后斜向等已有视角族，覆盖镜像方向 |
| 高度/俯仰 | 合法的低、中、高视角；高视角不等于必须顶视 |
| 焦距与距离 | 在共享渲染器和来源支持的范围内联合选择，保持适当投影尺寸与背景上下文 |
| 构图 | 动作区域位置、周边留白和支撑可见范围，检查三个对象及多次事件 |
| 裁剪 | 使用共同 near/far 契约，避免物体或场景被裁切 |

3obj 不总有唯一的“相撞方向”。相机参考轴由模板的初始几何与声明角色确定，例如首个入射方向和支撑法线；双向汇入按模板指定参考方向，不能让每次事件临时重置相机方位。零速度、共线或退化参考方向的 fallback 需显式定义并冻结。

现有 2obj 视角族可作候选，但其角度范围与 pair 可见性阈值不能直接视为适用于三物体。先按兼容性分配请求视角族，再只用 base 轨迹与画面检查确定候选；记录请求值、最终采用值和 fallback 原因，按最终视角统计覆盖，不能把“曾请求过”当成“已经生成”。

正式 3obj base 镜头采用双边物体占比约束：每个对象在整个 base 轨迹上的最小短边投影不低于画面短边 5%，候选选择以 10% 为目标，任一时刻最大长边投影不超过 25%。初始帧和所有必需接触帧前后各一帧必须完整处于事件安全边界内。其余非关键帧允许少量越过普通安全边界，其中真正出画的帧占比不超过 8%，最深越界不超过画面尺度的 3%；普通安全边界违反比例不超过 15%。这些限制逐对象验收，不能用三物体平均值抵消过小或过大的对象。

### 8.5 Base 镜头验收与 mask 边界

复用投影和包围盒基础计算，检查初始状态、全部关键事件前后、后段运动及整个轨迹的基本出画情况。接触瞬间允许合理重叠，不要求三者始终完全分开；但要能从前后运动辨认对象及事件。

每个物体分别满足投影尺寸、出画及遮挡要求，不能仅用三者平均值验收；跨对象最小值可以作为汇总，但需保留每对象结果。投影面积足够不代表没有遮挡，2D 包围盒相交也不等于真实遮挡。几何投影用于预筛，再以正式渲染检查关键帧；试产和复杂/被标记组做人工视频复核。没有可靠遮挡估计时，不把包围盒比例命名为精确可见面积。

关键事件按物理子步检测，但必须能在交付的 24fps 视频中理解。若 base 的两次事件间隔过短而在视频里完全不可区分，应在试产中调整该模板的初态时间范围，不能只因子步记录正确就判为观察合格，也不能只为个别组改变帧率。

候选镜头和有限的外观修正只依据 base，设有限候选列表与固定顺序，记录失败和 fallback；最终仍不合格的 base 进入对应的准入失败流程。可用预声明的较宽构图裕量，但不根据 sweep 的结果选择镜头。

默认生产不生成逐帧 PNG mask，也不新增默认必跑的 ID/depth pass。基础投影/几何检查、有限关键帧和人工视频复核构成首版路径，其检查覆盖和局限应写入报告。可见性检查不能暗中恢复此前移除的全量 mask 产物。

### 8.6 Sweep 可见性记录

派生运动可能离开 base 的可见区域。记录出画比例、对象可见性等诊断，不把这些变化当成重新筛选运动结果的条件。若整体观测策略存在系统性缺陷，应在试产阶段调整下一版统一策略，再重新冻结，而不是对个别 sweep 修改镜头、纹理或曝光。

### 8.7 正式媒体规格

| 项目 | 规格 |
|---|---|
| 分辨率 | 1280 × 720 |
| 帧率 | 24fps |
| 物理记录区间 | 0–4 秒闭区间 |
| 帧数 | 97 帧，含 t=0 与 t=4 |
| 编码与封装 | 沿用现有 H.264 MP4 规范及时间戳校验 |
| 逐帧 PNG mask | 默认不生成，不进入正式样本 |

闭区间采样的 97 帧与容器显示时长不能混为同一概念，验收沿用既有媒体契约，不能另加“容器时长必须恰好 4.000 秒”的冲突规则。

### 10.1 专用后端的特别风险

当前台球 resolver 在两个对象时选择 `billiards_two_object_v1`，其他数量选择旧 `billiards_v4`，后者声明允许 `[1, 3]`。这条旧三物体路径不代表满足本设计的单对象材料干预、统一 solver 证据和三物体运动验收。

接入新 3obj 台球时，必须显式选择审查过的执行路径，不因“不是两个对象”而自动落入旧分支。被动弹珠台和轨道弹珠也需要明确三物体分派，不能套用单球 fallback。

现有 `specialized_backend_registry.py` 要求多项标识唯一，包括 source schema。不能简单插入重复 schema 的记录来注册每一种对象数量。专用接入阶段应明确区分 source schema、family 与执行 adapter 的职责，以最小改动完成分派，保留旧入口行为。

```text
configs/
```

配置的唯一归属如下。解析器负责跨配置引用与冲突检查，不能采用“后加载的配置覆盖前者”的隐式优先级。

| 配置 | 唯一职责 |
|---|---|
| `three_object_motion_rules.json` | 模板 ID、角色、初态参数域、必需/允许/禁止事件、运动阈值和文本模板引用 |
| `three_object_scene_rules.json` | host/支撑/环境兼容、几何与布局边界、各运动适用的相机族与观察规则 |
| `three_object_sampling_matrix.json` | 引用合法模板与来源条件，定义物理/视觉覆盖维度、分配顺序和确定性 seed 策略 |
| `three_object_physics_sweep.json` | 对象数及公共 sweep 规则的已绑定覆盖参数 |
| `three_object_production_sampling.json` | 正式数量、比例和来源复用预算，试产后冻结 |
| `configs/datasets/three_object.json` | 正式输出根目录与对象数量 |

材质/纹理/HDRI 和通用渲染参数使用共享配置及资源清单，通过哈希引用，不复制三物体专属资产注册表。每个阈值只有一个归属，其他阶段接收同一解析结果；明确初态分离、运动有效性、数值完整性、镜头观察的不同阈值，不能为省文件把它们混成一个“quality”常量。

公共提取只针对明确重复内容：来源清单/lineage 读取从 `two_object_sources.py` 中拆出，原 2obj 的几何兼容筛选保留；对象身份、caption 与 span 绑定归 `dataset_contract`；物理接触采集归 `physics`；图连通性与运动语义归对应 `motion_rules`；投影与 shader 构造仍归现有渲染工具。数学上的 pair 几何函数可以对 AB、AC、BC 分别复用；双物体专属的整体运动/镜头策略不能直接用来验收三物体。

三物体 caption 首先扩展既有 identity 模块，只有模块复杂度确需拆分时才提取共享 caption 工具；文本模板与初态/角色绑定，不能 import 仿真结果来填最终结局。文本/身份、运动规则和物理执行通过明确输入传递，底层模块不依赖 CLI 编排，避免相互导入。

3obj coverage 接收已验证的来源池和解析规则，产出稳定 cell ID、候选顺序及数量报告；sampler 消费 cell 构造场景，不自行重做配额算法。三物体来源的组合空间不能通过复制双物体全部组合后再乘一次来源池生成，应采用按 shape/scale/host 条件检索和有界选择，先做可行容量预检。

编排复用 `dataset_generation.py` 的目录、计划、执行与恢复机制；base 替换和 sweep 停止调查是显式策略输入。若现有 2obj admission 中的共享阶段操作需要提取，就提取该操作，不复制整套 admission/recovery/resample CLI。新增特殊 family 时优先使用同一规则接口和共用球体执行器，不为每个 family 再创建一套发布器。

### 11.2 必须保持的职责边界

| 层 | 职责 | 不应承担的工作 |
|---|---|---|
| sampling | 从合法空间抽样，构造初始状态、来源和意图 | 根据 sweep 结果挑选候选 |
| motion/scene rules | 定义运动、兼容性和 base 语义 | 执行渲染或管理生产进程 |
| physics | 执行刚体动力学，记录真实状态与事件 | 添加中途引导力以凑出目标动作 |
| camera/rendering | 选择 base 镜头，按固定输入成像 | 修改物理轨迹使画面更符合模板 |
| admission | 区分 base 语义与 sweep 完整性，记录失败 | 把所有失败笼统转成重新采样 |
| release | 规范化、绑定、发布和验证文件 | 再次决定物理运动是否“好看” |

### 11.3 修改共享代码时的约束

先保存当前实现与测试结果，再做窄范围修改。新入口使用新的工作 ID 与源码版本；已有运行仍绑定其冻结代码。

回归覆盖 1obj/2obj 的代表性真实输入，检查对象身份、参数、轨迹、发布字段和目录契约。尽可能比较可复现物理数组和语义结果；不要把 ZIP 容器或 GPU 渲染输出的二进制差异一律解释成物理变化，也不能在数值差异出现时未经调查直接放宽容差。

旧 adapter 名称可以作为薄兼容入口保留，但执行核心不重复维护。不得静默改变旧 adapter 的物理行为。

| D1 最小闭环 | 一个 generic 三球顺序碰撞场景，跑通 metadata/caption → physics → 12 sweep → 正式尺寸渲染 → 暂存发布 | 三对象及文本绑定正确，只有 A 被干预，全部 13 条通过完整性与格式检查 |
| D2 Metadata 试产 | 约 120 个 generic 候选，按有效物理 cell 和条件视觉分配计划采样 | Metadata、来源/贴图绑定通过；物理和视觉覆盖分别有报告 |
| D3 物理试产 | 仿真 base；为通过的 base 派生完整 sweep | 按模板/角色统计失败；接触事件和三物体参与性可核查；无未解释的数值/绑定问题 |
| D4 视频试产 | 预选少量覆盖不同纹理、背景、光照、视角和运动的完整组，正式尺寸渲染并暂存发布 | 镜头可读，贴图正常，视觉输入组内一致；取得真实耗时 |
| D5 覆盖扩展 | 混合形状/新支撑、允许的外观变化、台球，再到另外两个专用 family | 各新增分支重复对应的 metadata、物理、媒体验证 |
| D6 生产冻结 | 确定支持范围、全部阈值、总量、物理与视觉配额、来源上限、代码版本 | 关键缺口关闭；缺失的覆盖单元有明确理由，不只挑高通过率模板 |
| D7 正式生产 | 按 checkpoint 分阶段执行、恢复、发布与全量验收 | 清单数量、完整组、哈希链、媒体与轨迹全部通过 |

120 是候选试产预算，不保证得到 120 个通过的 base，也不是四个模板永久各 30 条的配额。如果模板的合法覆盖单元不均等，应据此调整分配并在采样前记录。

视频试产可从通过 base 的组中按模板、角色、参数边界预先选组；每个选中组渲染全部 13 条。不能根据 sweep 是否继续碰撞、是否运动明显来选组。

如果试产发现规则需调整，保留原候选与失败证据，增加规则版本或换 work ID，不覆盖旧试产结果。

每个进入正式范围的模板都应有通过的代表组、应失败的反例和完整 13 条的干预/不变量验证。跨模板测试集覆盖“结果变化”和“正确干预但效果很小”两种情况，验证两者均被保留；不把响应幅度变成模板准入指标，也不要求每个模板都有相同的效果类别。人工审阅范围在试产报告中声明，不能用一个成功的 D1 演示替代全部模板与视觉维度的验收。

### 12.1 检查点与恢复要求

沿用 2obj 的阶段边界：计划 → metadata-only → base/sweep admission → base 相机确认 → 渲染准备 → 渲染 → 正式发布 → 验收。各阶段输入/输出和冻结范围按第 5.4 节执行。

计划冻结代码哈希、配置哈希、来源清单、对象数、目标列表、随机种子及采样请求。相机在准备成功后绑定到渲染执行计划。恢复时校验内容与执行证据，不仅判断“文件存在”。

制作阶段写入暂存目录，成功后再发布。物理语义不合格的 base 可以按冻结的候选顺序和上限替换；sweep 完整性失败停止调查。候选尝试和失败记录保留，不进行无界重试。

正式输出中的完整组是验收单位。失败场景、半成品、内部日志不得混入 canonical release。

## 14. 多样性、覆盖分配与生产规模

### 14.1 覆盖矩阵与统计单位

不能用“随机种子很多”代替多样性，也不能把一个 base 的 12 条 sweep 当作 12 个新场景。物理/视觉覆盖均以 base 组为主要统计单位；干预水平的覆盖单独报告。

| 维度 | 要覆盖的内容 | 至少报告的实际统计 |
|---|---|---|
| 分支与类型 | family、接触关系、唯一主运动模板 | 各类请求/候选/通过/发布组数；附加事件标签不重复计入模板总量 |
| 对象 | 角色有序形状组合、语义资产、尺寸与质量比、初态姿态 | 唯一来源数、组合数、角色分布、重复率 |
| 运动 | 滚动/滑动、相对方向、速度、偏心量、事件时间与顺序 | 合法参数分层、事件指标、模板退化率 |
| 物理场景 | 支撑类别、尺度、边界、专用 fixture | 实际 host/fixture 数及复用情况 |
| 纹理与材质 | 对象/支撑外观族、图案与尺度、颜色/反射属性 | 实际加载的来源/配方数及组合分布 |
| 背景与光照 | 环境类别、复杂度、HDRI/灯光与曝光方案 | 环境来源数、光照方案分布、视觉失败率 |
| 相机 | 方位族、高度、焦距/距离与构图 | 最终视角分布、每对象投影尺度、fallback/出画情况 |
| 干预角色 | A 在不同模板中的物理角色、对照中是否参与接触 | 模板内目标角色占比和对应 sweep 组数 |

纹理图像哈希、程序化配方哈希与最终视觉签名分开使用：同一张图缩放十次不是十种独立纹理来源；同一 HDRI 旋转多次也不增加 HDRI 来源数。来源数量与参数变化都报告，不互相冒充。

### 14.2 分层分配，避免组合爆炸和视觉捷径

1. 从规则构造合法的物理 cell：family、接触/运动模板、角色有序形状/尺度关系、物理场景、干预角色。先校验来源容量和必要几何条件。
2. 按确定的覆盖目标选择 cell，并在 cell 内以模板兼容方式采样速度、间距、偏心量、物性及姿态。小试产选择代表组合和边界，不宣称遍历全部合法组合。
3. 在每个物理候选的兼容来源中分配纹理、背景、光照和请求视角。对重要两两交叉保持覆盖，例如运动×场景、运动×相机、角色×颜色/纹理、形状×尺寸比；不追求八个维度全组合。
4. 经过 base 物理与视觉验收后，统计最终分布和 fallback。更难通过的 cell 先分析构造/观察问题；在冻结的尝试上限内补候选，不能静默将其额度挪给容易模板。
5. 试产报告驱动下一版配额调整；更改规则/范围后重新冻结。正式运行使用冻结配额与缺额策略，不在运行中按成功率任意改类。

对象外观若已经随来源绑定，应在步骤 1–2 联合选择满足物理与外观要求的来源；步骤 3 只分配剩余可变且已声明的视觉项，不更换物理候选中的对象资产或材质先验。真正改变几何、物性或物理环境的外观选择必须返回候选构造并重新计算物理签名与准入，不能当成后期换背景。

在允许范围内避免“连锁总在实验室”“目标 A 总是红色”“某质量档总配某纹理”“汇入总是俯视”等单一绑定。物理、外观与相机受兼容性约束，不能强求统计完全独立；应检查可行条件下的交叉分布，记录不可覆盖组合的原因，不能靠不合理场景凑均衡。

每个组的种子由主种子、稳定 cell ID、候选编号和用途标签确定，物理、外观、相机用独立的确定性子种子；不使用进程随机 hash 或依赖 worker 完成顺序的全局随机流。所有 sweep 复用 base 的视觉输入与对应种子。改 worker 数、断点恢复或重排请求，不应改变同一候选的定义。

确定性 seed 还不够：对象/host 复用预算、去重占位和候选接受若按 worker 完成先后提交，最终样本仍可能变化。因此先按稳定 cell/候选顺序分配来源，冻结可执行计划；需替换候选时，也按同一确定顺序提交准入与预算结果，并行只改变执行速度。更改配额或规则属于新计划，不要求它与旧计划产生完全相同的样本集合。

### 14.3 容量、重复与失败后的覆盖

采样前输出对象池、host 池、纹理/HDRI 资源可用量和来源复用上限的必要容量界。廉价容量预检通过仍不保证物理和相机可行，二者需要分别报告。

请求数、候选数、唯一物理数、base 物理通过数、最终视觉通过数、发布组数逐阶段统计。视觉 fallback、被拒来源和缺失 cell 单独列出，不能只展示发布样本的好看分布。正式缺额时明确失败或按预先声明政策处理，不从其他类别偷偷补齐。

以物理签名检查重复，以视觉签名检查外观重复，以 lineage 跟踪来源复用；对同一物理状态的外观变体设显式预算。避免同时使用“必须全部物理唯一”和“无限换皮扩增”两种冲突口径。

首轮约 120 个候选主要用于发现错误与估计可行性，不能据此证明所有类型、纹理、视角及复杂分支都有充分多样性。正式支持范围和每个维度的最低覆盖量在 D6 前明确，数值通过试产确定。

### 14.4 总量和性能计算

本版单目标方案中，若 base 数为 B，总样本数为 `13B`，sweep 数为 `12B`。按完整组确定数量，不通过删除部分 sweep 凑整数。

| 仅作计算示例 | Base | Sweep | 总条数 |
|---|---:|---:|---:|
| 不超过 40,000 的完整组 | 3,076 | 36,912 | 39,988 |
| 最接近 40,000 的完整组 | 3,077 | 36,924 | 40,001 |

40k 是沿用此前讨论的示例，不是本次 3obj 已确定的生产规模。

小规模通过率用于估算候选需求，应报告样本量和不确定性，不能当成固定成功率。物理与视觉配额按本节共同规划，不在物理采样完成后才临时补外观多样性。

性能估算使用正式尺寸试产实测的物理、渲染、I/O、发布校验与恢复成本，并测量子步事件记录和复杂纹理带来的开销。资源按启动时实际可用量安排，不将某次 GPU 空闲快照写成长期生产容量。

## 15. 本版开发完成的判定

3obj 生成能力完成需要：第 12 节适用开发阶段完成、第 13 节行为验收通过、第 14 节声明的物理与视觉覆盖有实际证据；共同目录/schema 与 1obj/2obj 回归通过。尚未实现的模板或分支必须列为未支持，不能通过“底层数量允许 3”宣称全部能力完成。

开发完成、正式生产完成、下游训练导出完成是三个不同阶段。本项目首先交付可验收的 3obj 生成与发布能力；不据此声称训练数据切分、条件构造或训练接入已经完成。
